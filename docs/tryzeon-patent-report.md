# 「合身真相」研究方向分析

> 核心構想：用戶提供一張照片＋店家提供尺寸表，系統以物理模擬計算這件衣服穿在
> 該用戶身上哪裡緊、哪裡鬆，並將結果呈現在擬真的試穿照上。
>
> 現況：Tryzeon 目前的試穿照為純生成式（`supabase/functions/_shared/tryon/image.ts`
> 使用 `gemini-2.5-flash-image`），無任何 3D 或物理成分。「合身真相」等於在這條
> 生成管線旁新增一條**幾何／物理管線**，兩者最後在同一張圖上會合。

## 一、問題拆解：四個研究子問題

「一張照片＋一張尺寸表 → 物理模擬 → 畫在擬真試穿照上」技術上是四個獨立研究
問題的串接：

| 子問題 | 輸入 | 輸出 |
|---|---|---|
| **A. 人體重建** | 用戶單張照片（＋身高） | 帶真實尺寸的 3D 人體模型 |
| **B. 服裝數位化** | 店家尺寸表（＋品類、材質） | 可模擬的 3D 服裝網格 |
| **C. 物理模擬與合身計算** | A 的人體 ＋ B 的服裝 | 每個部位的緊／鬆量化圖（fit map） |
| **D. 視覺化回擬真照** | C 的 fit map ＋ 試穿照 | 標註了緊鬆的擬真試穿照 |

成熟度差異很大：B、C 在服裝 CAD 業界已相當成熟；A 是學術界活躍但已可用的領域；
**D 的第二階段（讓照片本身反映緊繃皺褶）是目前市場與文獻的空白，也是專利最有
價值的落點。**

## 二、各子問題的研究方向與具體做法

### A. 單張照片 → 帶尺寸的 3D 人體

標準做法是估計 **SMPL / SMPL-X 參數化人體模型的 shape 參數（β）**。SMPL 以約
10 個係數描述體型，可直接從 β 量出胸圍、腰圍、臀圍、肩寬——正是對比尺寸表
所需的量。

1. **起點模型**：SHAPY（CVPR 2022，專攻 shape 精度而非 pose）、HMR 2.0，或商用
   SDK（3DLOOK、Nettelo）。SHAPY 特別重要：多數人體重建論文只在乎姿態，它是
   少數以「圍度誤差公分數」為指標的工作。
2. **解決尺度歧義（最關鍵）**：單張照片在數學上無法確定絕對尺寸——160cm 和
   180cm 的人可投影出幾乎相同的影像。**必須要求用戶輸入身高（最好加體重）作為
   錨點**，沒有替代方案。身高＋體重＋照片輪廓聯合估 β，圍度誤差可壓到 ±2–4cm。
3. **提升精度選項**：正面＋側面兩張照片（誤差可再減半）、或短影片轉多視角。
   產品上建議「一張照片能用、兩張更準」。
4. **驗證方法**：招募 50–100 人皮尺實量胸腰臀，對比模型輸出。此資料集同時是
   專利實施例的證據。

### B. 尺寸表 → 可模擬的 3D 服裝

尺寸表只有幾個數字，要變成可物理模擬的 3D 網格，正確做法是**參數化版型模板
（parametric sewing pattern）**：

1. 為每個品類（T恤、襯衫、西裝褲、洋裝…）建一個參數化 2D 版型模板——服裝
   打版的數位化。一個品類做一次，之後所有店家的尺寸表都能套。
2. 尺寸表數值直接映射到版型參數（衣長 → 版片長度，胸圍 → 前後片寬度之和）。
3. 版片縫合＋初次披掛（draping）到標準人體，得到 3D 服裝網格。學術對應：
   **GarmentCode**（程式化版型描述語言，SIGGRAPH Asia 2023）、NeuralTailor、
   Sewformer；工程上也可直接用 CLO3D / Marvelous Designer 的 API 做資產管線。
4. **布料物理參數（彈性模量、克重、彎曲剛度）是實務上最大的缺口**——尺寸表
   不會提供。可行做法：建「成分 → 物理參數」對照庫（95% 棉 5% 彈性纖維的
   平織 vs 針織各一組參數），從商品成分標估計。此誤差是全鏈最難消除的，
   v1 接受粗分類（彈性大／中／無彈）即可。

### C. 物理模擬 → 緊鬆量化

理論最成熟的一段。把 B 的服裝披掛到 A 的人體上做布料模擬，從結果讀出三種訊號：

- **應變圖（strain map）**：每一小塊布料被撐開的比例。布被身體撐開 >3–5% ＝
  「緊」，直接對應體感緊繃。
- **鬆量圖（ease map）**：布料到皮膚的距離（clearance）。距離大＝「鬆」，可量化
  為「腰部多出 6cm 鬆量」。
- **接觸壓力**：緊身衣物的壓迫感，選配。

模擬器兩條路線：

1. **傳統模擬器**（XPBD、Projective Dynamics、C-IPC；NVIDIA Warp 有現成 GPU
   實作）：準、慢（秒級到分鐘級）、無需訓練資料。**v1 用這個**——現有 try-on
   本來就是異步 job（`runTryonJob`），多等 30 秒可接受。
2. **神經披掛網路**（HOOD、ContourCraft、DrapeNet）：毫秒級、可微分，但要先用
   傳統模擬器生成訓練資料。是 v2 的降本手段，非 v1 必需。

重要工程判斷：**存在一條完全不用物理模擬的捷徑**——直接比較「服裝圍度 vs
身體圍度＋標準鬆量」，即 Fit Analytics、True Fit 等尺碼推薦公司的做法。它做
不出「畫在照片上的連續緊鬆分布」，但可當 Phase 0 的產品驗證；同時提醒：專利
claim 必須明確綁定「物理模擬產生**空間連續**的合身圖」，才能與這類先前技術
區隔。

### D. 把合身結果畫回擬真試穿照

全鏈最有專利價值、最需要原創研究的一段。兩條路線，建議依序做：

**路線 1：投影疊加（工程問題，可先交付）。** 現有 Gemini 管線生成試穿照 →
對試穿照跑 SMPL pose 估計，把模擬用 3D 人體對齊到照片中的姿態 → 將 3D fit map
投影成 2D，以半透明熱圖疊在照片上（紅＝緊、藍＝鬆），加文字標註（「肩部緊
2cm」）。難點是生成照片的姿態與 3D 模擬體的配準，但皆為已知技術的組合。

**路線 2：合身條件化生成（研究問題，專利核心）。** 讓照片**本身**呈現合身
狀態——緊處有拉扯橫褶、鈕扣間隙，鬆處有垂墜堆疊。做法：把物理模擬輸出
（披掛後服裝的 depth map / normal map / 皺褶場）作為生成模型的空間條件
（ControlNet 式注入，或作為 Gemini 類模型的參考影像＋結構化描述）。目前所有
商用 VTON（含現用的 Gemini）生成的都是「這件衣服的平均穿法」，完全不反映
這個人的尺寸——**「物理模擬結果驅動生成影像的皺褶與垂墜」這個閉環是目前
市場和文獻的空白**，claim 應重點覆蓋。

## 三、端到端管線

```
用戶照片＋身高 ──► [A] SMPL 體型估計 ──► 3D 人體（帶真實尺寸）
                                              │
店家尺寸表＋成分 ─► [B] 參數化版型＋材質庫 ─► 3D 服裝
                                              │
                                    [C] 布料物理模擬
                                              │
                              strain / ease fit map（3D）
                                              │
用戶照片 ──► Gemini 生成試穿照 ──► [D] pose 對齊 ─► 疊加熱圖（路線1）
                        ▲                          或
                        └── 模擬 depth/normal 條件化生成（路線2）
```

## 四、分階段路線圖

### Phase 0（~2–3 個月）：圍度比對版，驗證產品價值

不做物理模擬：用戶身高體重＋照片粗估三圍（現成模型），和尺寸表做逐部位圍度
比較，在現有 Gemini 試穿照上疊文字標註（「胸部合身、衣長偏短 3cm」）。目的是
用最低成本驗證「用戶到底在不在乎合身資訊」，同時開始收集真人試穿的 ground
truth 資料。

### Phase 1（~6–12 個月）：物理模擬＋熱圖疊加

SHAPY 級人體重建 → 3–5 個品類的參數化版型 → NVIDIA Warp 或 CLO3D 管線做模擬
→ strain/ease 熱圖投影疊加到試穿照。這是專利說明書裡完整實施例的最小版本。

### Phase 2（12 個月＋）：合身條件化生成

用 Phase 1 的模擬器批量生成〈人體×服裝×尺碼 → 披掛結果〉配對資料，訓練／
微調生成模型接受模擬幾何作為條件，讓照片的皺褶垂墜真實反映該用戶穿該尺碼的
樣子。這是技術壁壘所在。

## 五、專利定位：先做先前技術檢索

此領域既有技術不少，claim 寫法決定專利能否立住：

- **CLO3D / Browzwear** 的 fit map（應變熱圖）在服裝 CAD 是成熟功能——但輸入
  是專業 3D 資產，輸出畫在虛擬模特上，**不是**消費者照片。
- **True Fit / Fit Analytics（已被 Snap 收購）**：尺碼推薦，無物理模擬、無視覺化。
- **Amazon「Made for You」、Walmart Zeekit、3DLOOK**：各佔一角（量體、換裝、
  掃描），沒有端到端閉環。

可防禦的 claim 應是**組合與閉環**：「消費者單張照片＋商家尺寸表 → 自動建體＋
自動建衣 → 物理模擬產生空間連續合身圖 → 將合身圖配準並呈現於該消費者的擬真
試穿影像」，並把**路線 2（模擬結果條件化生成影像）寫成獨立 claim**——最難
繞開的部分。動手前建議花小錢做正式的 FTO／先前技術檢索。

## 六、三大風險與對策

1. **誤差累積**：人體 ±2–3cm、版型近似、布料參數靠猜——疊加後「差半個尺碼」
   的判斷可能不可靠。對策：輸出設計成三檔（明顯緊／合身／明顯鬆）＋置信度，
   不假裝能精確到公分；用真人試穿資料持續校準。
2. **店家端資料品質**：尺寸表常不準或缺項（沒有彈性、沒有克重）。對策：品類
   模板容錯設計＋成分推估材質庫，把店家 onboarding 成本壓到「貼一張現成尺寸表」
   為止。
3. **姿態配準**：生成照片裡的人和 3D 模擬體姿態不一致，熱圖會貼歪。對策：
   反過來讓模擬體先對齊照片 pose 再模擬（pose-conditioned draping）——此細節
   本身也可寫進專利。

## 總結

A、B、C 三段都是已知技術的工程整合（難在精度校準，不在原理），真正的研究
空白和專利核心在 **D 的路線 2——物理模擬的合身結果驅動生成式試穿照的皺褶與
垂墜**。建議 Phase 0 先用圍度比對＋現有 Gemini 管線驗證需求，同時啟動先前
技術檢索，把 claim 重心押在端到端閉環和條件化生成上。
